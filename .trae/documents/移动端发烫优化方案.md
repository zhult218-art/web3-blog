# 移动端访问发烫优化方案

## Context（为什么要做）

用户反馈：**手机访问站点会明显发烫**，多位用户同样反馈。经代码排查，根因是「常驻全屏动画」持续占满 GPU/CPU：

| 问题 | 证据 |
| --- | --- |
| 每个页面都常驻**全屏 WebGL 3D 背景** | `dynamicBg` 默认 `true`（[siteSettings.js](file:///z:/project/myblog/web3/frontend/src/stores/modules/siteSettings.js#L51)），`Web3Layout`/`BlogLayout` 无条件渲染 `ThreeBackground` |
| 每页还常驻一个**粒子连线画布** | [ParticleBackground.vue](file:///z:/project/myblog/web3/frontend/src/components/layout/ParticleBackground.vue)：100 粒子，每帧 O(n²)≈4950 次距离计算 + 逐线 `stroke()` |
| **文章页重复挂载了一份** | [post.vue](file:///z:/project/myblog/web3/frontend/src/views/blog/post.vue#L3-L4) 又渲染了一次 `ThreeBackground`/`ParticleBackground`（布局已提供）→ 文章页出现 2 个 WebGL 上下文 + 2 个粒子画布 |
| 两个背景**切后台不停** | 无 `visibilitychange` 处理，切 tab / 息屏后仍持续渲染 |
| 无移动端降级 | [ThreeBackground.vue](file:///z:/project/myblog/web3/frontend/src/components/layout/ThreeBackground.vue#L128-L129)：`antialias: true`、`preserveDrawingBuffer: true`、`setPixelRatio(min(dpr, 2))`、760 个加色混合粒子 + 3 层自定义 shader 圆环（10×240 段），全屏逐像素 `sin/pow/smoothstep` |
| 大面积实时模糊 | 全站约 118 处 `backdrop-filter`，[main.css](file:///z:/project/myblog/web3/frontend/src/assets/styles/main.css#L616-L617) 有 `blur(24px)` 强模糊 |

> 注：App.vue 的动态壁纸视频**已有**降级（`prefers-reduced-motion` + 核数 + 切后台暂停），不是本次优化重点，保持不动。

**目标**：显著降低手机端持续 GPU/CPU 占用与发热 —— 桌面观感**完全不变**；手机端接受「背景由流动改为静态 + 大面板模糊略减弱」。

## 方案（分层，按建议默认执行）

### 第 1 层：消除纯浪费（手机/桌面都受益，零视觉损失）

1. **删除文章页重复挂载**
   - [post.vue](file:///z:/project/myblog/web3/frontend/src/views/blog/post.vue#L3-L4) 移除模板里的 `<ThreeBackground />` `<ParticleBackground />`，并删除 [第 207–208 行](file:///z:/project/myblog/web3/frontend/src/views/blog/post.vue#L207-L208) 的两个 import。
   - 理由：`BlogLayout` 已渲染这两个背景，文章页再渲染纯属重复，直接砍掉一半开销。

2. **两个背景接入「切后台暂停」**
   - `ThreeBackground`：`document.hidden` 时 `cancelAnimationFrame(raf)`；恢复可见时重启 `animate()`。监听 `visibilitychange`，并在 `onBeforeUnmount` 移除监听。
   - `ParticleBackground`：同样处理（`raf` 暂停/恢复）。
   - 效果：用户切到别的 App / 息屏后，画面停止渲染，发烫与耗电立刻归零。

### 第 2 层：移动端自适应降级（桌面不变，手机观感略有变化）

新增一个轻量设备能力判断（新增 `frontend/src/composables/useDeviceCapability.js`，供两个背景组件复用）：

- `isMobile = matchMedia('(max-width: 768px)').matches || matchMedia('(pointer: coarse)').matches`
- `reducedMotion = matchMedia('(prefers-reduced-motion: reduce)').matches`
- `lowEnd = navigator.hardwareConcurrency != null && navigator.hardwareConcurrency <= 4`
- `staticBg = isMobile || reducedMotion || lowEnd` → 只渲染**一帧静态画面**，不启动 RAF 循环（保留视觉，但不持续耗电）

据此改造：

- **[ThreeBackground.vue](file:///z:/project/myblog/web3/frontend/src/components/layout/ThreeBackground.vue)**
  - `antialias: !isMobile`（手机关抗锯齿）
  - `setPixelRatio(Math.min(devicePixelRatio, isMobile ? 1 : 2))`（手机像素量最多降到 1/4）
  - `preserveDrawingBuffer: isMobile ? false : true`（保留桌面端原有的「路由切换白闪」修复，手机上省掉这项昂贵设置）
  - 粒子数 `760 → isMobile ? 280 : 760`
  - `staticBg` 时：渲染一帧后不再 `requestAnimationFrame`（可保留缓慢自转的极简版或不转）
- **[ParticleBackground.vue](file:///z:/project/myblog/web3/frontend/src/components/layout/ParticleBackground.vue)**
  - 粒子数 `100 → isMobile ? 40 : 100`
  - 手机端**跳过 O(n²) 连线**（连线是小尺寸屏上几乎看不见的细节，但消耗最大）
  - `staticBg` 时静止一帧

> `site.featureOn('dynamicBg')` 开关与其默认值保持不变，用户仍可在后台自行彻底关闭背景；本次只是让手机「自动降级」而非改默认。

### 第 3 层：毛玻璃与常驻 CSS 动画（仅移动端/低动效偏好）

- **[main.css](file:///z:/project/myblog/web3/frontend/src/assets/styles/main.css)**：新增 `@media (max-width: 768px)` 覆盖
  - `.backdrop-strong { backdrop-filter: blur(10px) }`（原 24px）
  - `.backdrop-medium { backdrop-filter: blur(6px) }`（原 12px）
  - 观感接近，但大面积实时模糊的 GPU 开销大幅下降。
- 新增 `@media (prefers-reduced-motion: reduce)`：关闭 `.glitch`/`neonPulse`/`scanline`/`holoSlide`/`cloud-drift`/`animate-float`/`.pulse-ring` 等**常驻无限动画**（`animation: none`）。

## 验证方式

1. **构建**：`node node_modules/vite/bin/vite.js build` 必须通过（当前项目用便携版 node，见此前构建方式）。
2. **切后台**：桌面 Chrome 打开站点 → 切到其它 tab → DevTools Performance / 任务管理器 CPU 占用应降到接近 0；切回页面动画恢复。
3. **文章页无重复**：打开 `/blog/post/:id`，Elements 面板中 `<canvas>` 数量应为背景一个（不再是两个 WebGL/粒子叠加）。
4. **移动端降级**：DevTools 设备模拟（或真机）打开站点 → 背景为静态、滚动流畅；`prefers-reduced-motion: reduce` 模拟下无无限动画。
5. **桌面无回归**：桌面端背景仍流动、路由切换无白闪、模糊观感不变。
6. 可用 browser_use 打开本地地址检查控制台无报错、WebGL 上下文正常。

## 预期效果

- 手机端：常驻的全屏 WebGL 与 O(n²) 粒子计算基本停掉 → 发烫与掉电显著改善。
- 桌面端、以及已登录后台的既有配置：观感与行为**零变化**（除切后台时暂停，这是纯收益）。
