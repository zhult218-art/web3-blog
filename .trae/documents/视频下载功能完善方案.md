# 书影音·视频下载功能完善方案

## Context（为什么要改）

用户报告：**书影音 → 视频 →「下载」标签粘贴 URL 点「开始下载」，提示成功但「在线视频」里始终没有这条视频。**

经实测定位，根因有 4 层（均已用运行证据确认）：

1. **请求实际落到 Java media-service（8085），不是 py-service。**
   axios `baseURL=/api`，而 Vite 代理 [vite.config.js](file:///z:/project/myblog/web3/frontend/vite.config.js#L23-L27) 对 `/api` 做 `rewrite: path => path.replace(/^\/api/, '')`（**剥掉 /api**）再转网关 8080；网关 `Path=/video/**` → media-service。
   证据：`GET http://localhost:8085/video/list` 返回 24 条种子数据，结构为 `{data:{records:[{id,title,description,url,cover,duration,tags,episode,createdAt}]}}`，与前端 [media/index.vue](file:///z:/project/myblog/web3/frontend/src/views/media/index.vue#L42-L58) 使用的字段**完全一致**。
   （py-service 的 `/api/video/list` 直连 9006 返回 `total:0`，浏览器根本走不到——那是另一套平行实现。）

2. **yt-dlp 与 ffmpeg / ffprobe 在本机完全不存在。**
   `shutil.which('yt-dlp')` → None，venv 内 `yt_dlp` 模块不存在，`C:\tools` 下无 ffmpeg，PATH 无 ffmpeg。
   而 [VideoService.java](file:///z:/project/myblog/web3/backend/media-service/src/main/java/com/web3/media/service/VideoService.java#L165-L183) 第 166 行 `cmd.add("yt-dlp")` 后 `pb.start()` → Windows 直接抛 `CreateProcess error=2 系统找不到指定的文件`。

3. **失败被前端当成成功（"假成功"）。**
   [VideoController.java](file:///z:/project/myblog/web3/backend/media-service/src/main/java/com/web3/media/controller/VideoController.java#L136-L141) 捕获 IOException 后走 `ApiResponse.fail(500, ...)`，而 `ApiResponse.fail` 返回的是 **HTTP 200 + body `{code:500}`**。axios 因 HTTP 200 不抛异常 → [media/index.vue](file:///z:/project/myblog/web3/frontend/src/views/media/index.vue#L207-L218) 无条件执行 `dlResult = {ok:true, msg:'✓ 下载成功，去「在线视频」查看'}`。
   这正是用户看到的现象：**提示成功，列表无变化**。

4. **同步阻塞 + 前端 15s 超时必冲。**
   下载在 HTTP 请求线程内同步执行，`proc.waitFor(30, TimeUnit.MINUTES)`；而 axios `timeout=15000`（[request.js](file:///z:/project/myblog/web3/frontend/src/api/request.js#L20-L23)）。即使装好 yt-dlp，稍长视频也必然客户端超时。

5. 下载成功后前端仍停在「下载」tab，用户看不到结果（虽有 `loadVideos()` 刷新但不可见）。

**目标**：让下载真正可用，并借鉴 `Z:\project\downvid-main` 的任务/进度模型，做成「粘贴 URL → 实时进度 → 自动出现在在线视频」。

## 方案

### 1. 安装工具（沿用 `C:\tools` 约定，不动系统 PATH）
- **ffmpeg 静态构建**（含 `ffmpeg.exe` + `ffprobe.exe`）→ `C:\tools\ffmpeg\bin`
  （ffprobe 是 media-service 探测时长必需；ffmpeg 是 yt-dlp 合并 `bestvideo+bestaudio` 必需）
- **yt-dlp** → `C:\tools\yt-dlp\yt-dlp.exe`（官方 standalone exe，不依赖 Python 环境）
- 根 `.env` 新增：
  ```
  YTDLP_PATH=C:\tools\yt-dlp\yt-dlp.exe
  FFMPEG_PATH=C:\tools\ffmpeg\bin\ffmpeg.exe
  FFPROBE_PATH=C:\tools\ffmpeg\bin\ffprobe.exe
  ```
- media-service `application.yml` 读取环境变量（Java 显式调用绝对路径，避免依赖 PATH）。

### 2. media-service：下载改异步任务 + 进度

**新增** `config/MediaDownloadProperties`（`@ConfigurationProperties("media.download")`）：
`ytdlpPath` / ffmpegLocation / timeoutMinutes / concurrency。

**新增** `service/DownloadTaskManager`（`@Component`）：
- `ConcurrentHashMap<String, DownloadTask>` + 固定线程池（并发 1~2，借鉴 downvid 的队列+并发约束，防 CPU/带宽打满）
- `DownloadTask` 字段：`taskId / status(downloading|merging|success|failed) / percent / speed / eta / title / error / videoId`

**重写** [VideoService.downloadFromUrl](file:///z:/project/myblog/web3/backend/media-service/src/main/java/com/web3/media/service/VideoService.java#L149-L239) 的 yt-dlp 调用，借鉴 [ytdlp.ts](file:///Z:/project/downvid-main/electron/download/ytdlp.ts#L113-L179)：

| 参数 | 作用 |
|---|---|
| `-f <清晰度映射>` | 沿用现有 switch（best/1080p/720p/480p） |
| `--merge-output-format mp4` | 合并为 mp4 |
| `--no-playlist --playlist-items 1` | 只取单视频 |
| `--newline --progress --progress-template '<结构化模板>'` | **结构化进度**，替代现在逐行扫 `[download] xx%` |
| `--http-chunk-size 10M` | downvid 实测：单连接被 CDN 限速时**提速约 30×**，对不支持 Range 的服务器自动退化 |
| `--concurrent-fragments 4` | HLS/DASH 分片并发 |
| `--ffmpeg-location <目录>` | 传目录而非文件，yt-dlp 会同时找 ffmpeg/ffprobe |
| `--print after_move:filepath` | 精确拿到最终文件路径（避免 `{id}.mp4` 猜测落空） |
| `--write-subs/--convert-subs srt` | 保留现有字幕选项 |
| `--proxy` | 复用 `.env` 代理（YouTube 等场景需要） |

- 下载完成 → `ffprobe` 取时长（现有 try/catch 保留）→ `Video` 落库（`url=/video/file/{uuid}.mp4`）→ 任务置 `success` 并记 `videoId`
- 失败 → 任务置 `failed` + 带回 yt-dlp stderr 尾部可读信息；**清理 `.part`/`.ytdl` 残留**（借鉴 `cleanupLeftovers`）
- 超时 → `destroyForcibly()` + 明确错误文案

**Controller 改造** [VideoController.java](file:///z:/project/myblog/web3/backend/media-service/src/main/java/com/web3/media/controller/VideoController.java#L126-L142)：
- `POST /video/download` → 建任务、**立即返回 `{taskId}`**（不再阻塞）
- 新增 `GET /video/download/{taskId}` → 返回 `{status,percent,speed,eta,title,error,videoId}`（需登录 `AuthUtils.requireUserId`）
- `GET /video/list`、`GET /video/file/{filename}` 保持不变

### 3. 前端：进度 UI + 修假成功 + 自动跳转

[frontend/src/api/media.js](file:///z:/project/myblog/web3/frontend/src/api/media.js#L33-L34)：
- `downloadVideoFromUrl` → 返回 `{taskId}`
- 新增 `getDownloadTask(taskId)`

[frontend/src/views/media/index.vue](file:///z:/project/myblog/web3/frontend/src/views/media/index.vue#L203-L223)：
- **先校验 `res.code`**：非 200 一律按失败处理并展示 `res.message`（直接消灭"假成功"）
- 拿到 `taskId` 后轮询（1s 递归 `setTimeout`），**组件卸载 / 离开下载 tab 时清理定时器**（项目既有约定：前端定时器必须显式清理防内存泄漏）
- 新增进度条：`下载中 42% · 3.2MB/s · 剩余 00:35`；`merging` 显示「正在合并音视频…」
- 成功后：`toast.success` → `await loadVideos()` → **`videoTab='online'` 自动切到「在线视频」**并高亮新视频（修掉"下载了却看不到"）
- 失败：原样展示后端 message（yt-dlp 真实报错）

### 4. 明确不做（控制改动面）
- **不动** py-service 的平行 `modules/video`（浏览器走不到它，保持现状）
- **不加**视频归属 userId（media-service 的 `videos` 表无 user_id，「在线视频」现状是全局共享，本次不改变该语义）
- **不实现** downvid 的直链分段/断点续传（`direct.ts`），普通 yt-dlp 链路已覆盖需求

## 验证

1. **工具就绪**：`& C:\tools\yt-dlp\yt-dlp.exe --version`、`& C:\tools\ffmpeg\bin\ffmpeg.exe -version`、`...\ffprobe.exe -version` 均正常输出。
2. **重新打包重启（注意两个坑）**：
   - 运行中的 jar 被锁 → 先 `Stop-Process` 掉 PID 16400 的 8085 进程
   - 重启**必须先加载根 `.env`**（JWT_SECRET 缺失会 fail-fast，项目既有约定）
   - `mvn -pl media-service -am package`
3. **后端直连验证**：
   - `POST http://localhost:8085/video/download`（带 JWT + `{url,quality,subtitle,tags}`）→ 立即返回 `{data:{taskId}}`
   - 轮询 `GET /video/download/{taskId}` 直到 `status=success` 且 `videoId` 非空
   - `GET /video/list` 出现新记录，且 `url` 指向 `/video/file/xxx.mp4` 可播放
4. **浏览器端到端**：`/media` → 视频 → 下载 → 粘贴 B站短链接 → 进度条走到 100% → 自动切到「在线视频」看到新视频并可播放。
5. **反例**：粘贴一个无效 URL，前端应显示真实失败原因（如 `ERROR: Unsupported URL`），**而不是「✓ 下载成功」**。
