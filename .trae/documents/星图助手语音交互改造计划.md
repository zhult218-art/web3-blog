# 星图助手语音交互改造实施计划

## 1. 背景与目标

**现状**：`frontend/src/components/common/XingTuAssistant.vue`（1636 行）已具备唤醒词、Web Speech 识别、Edge TTS 播报、本地导航命令（`LOCAL_CMDS`）、后端 `jarvis /jarvis/recognize`、Agent 流式兜底。但**不流畅**，根因三处：

1. **无打断（no barge-in）**：[XingTuAssistant.vue#L555-L573](file:///z:/project/myblog/web3/frontend/src/components/common/XingTuAssistant.vue#L555-L573) 的 `speak()` 开口即 `stopListening()`，且 `if (isSpeaking.value) return` —— 助手说话期间用户无法插话。
2. **TTS 首音延迟大（非流式）**：[edgeTts.js#L194-L215](file:///z:/project/myblog/web3/frontend/src/api/edgeTts.js#L194-L215) 的 `speakEdge()` 串行合成**全部句子**再拼成一个 mp3 blob 播放，首句必须等整段合成完。
3. **轮次切换抖动（无端点检测）**：[XingTuAssistant.vue#L1062-L1076](file:///z:/project/myblog/web3/frontend/src/components/common/XingTuAssistant.vue#L1062-L1076) 靠 `onend` 后 100ms 硬重连 + `isFinal` 判定，无静音时长判断，出现"一下获取一下获取不上"的观感。

**目标**：实现**流畅的全双工语音对话**（可随时打断、首句秒出、轮次平滑），并且助手能**主动引导用户完成操作**（语音导航 + 页面元素高亮）。

## 2. 三个开源项目分析与取舍

| 项目 | 核心机制 | 本计划采用 | 不采用 |
|---|---|---|---|
| **AsLive-main**（最贴合，Web 全双工） | `static/pcm-processor.js` AudioWorklet 采集 16kHz Int16；`api_server.py` WS 全双工；Silero VAD(512 样本/32ms 帧) 判定开口→`cancel` 未完成任务 + 下发 `interrupt`；FunASR `paraformer-zh-streaming` 增量识别；LLM 流式按句切分 → TTS 并发合成 → 按序回传 `audio`；`session_id` 隔离丢弃陈旧音频 | AudioWorklet PCM 采集、WS 全双工、VAD 驱动 barge-in、LLM 句子流式切分、session 隔离、前端音频队列按序播放、`getUserMedia` 开启 `echoCancellation` | Kokoro ONNX TTS、FunASR、`torch.hub` 拉 Silero（依赖重、下载大） |
| **MoeChat-main** | `utils/pysilero` VADIterator 流式切分 + `isSpeakFinish` LLM 端点判定；`core/chat_api_v4.py` `text_tts_queue`/`res_queue` 双队列流水线；`agent.interrupted` 标志取消生成 | "双队列流水线 + interrupted 取消态"思想；端点判定**简化为静音时长**（不额外调 LLM 判句） | StreamProcessor 全量重写、情感/激素引擎、MCP 插件体系 |
| **wukong-robot-master** | `robot/Conversation.py` 会话状态机（`matchPlugin`/`immersiveMode`/`interrupt`）；`robot/Brain.py` 技能插件 `isValid→handle` 分发；`say()/stream_say()` 分句并行 TTS；技能 `restore()` 沉浸模式 | **技能/意图路由**（导航技能）、**引导**（沉浸模式 → "下一步建议"）、分句并行 TTS 思路 | snowboy 唤醒、硬件驱动(LED/BCI)、腾讯/百度云端 ASR/TTS |

**结论**：以 **AsLive 的"浏览器 AudioWorklet + WS 全双工 + VAD 打断"** 为主干，吸收 **MoeChat 的队列/取消态** 与 **wukong 的意图→技能→引导** 编排，全部落在本项目既有栈（Vue3 前端 + py-service 9006 + Edge TTS + jarvis）上实现；**不引入 torch / funasr / Kokoro / snowboy** 等重依赖。

## 3. 架构决策（Assumptions & Decisions）

1. **TTS 保留前端 Edge TTS**，但改为**按句流式播放**（并发合成 + 按序播放）。无需服务端 TTS 依赖，天然支持 `stopEdgeSpeech()` 打断。
2. **ASR 主通道仍是浏览器 Web Speech**（Chrome/Edge 云端，准确且零服务端依赖）；服务端 faster-whisper 流式识别列为**可选升级**：`py-service` venv 当前未装 `faster-whisper/torch/funasr`，`asr.py` 必须做能力探测降级。
3. **VAD 用服务端纯 numpy 能量 VAD**（零新增依赖，`numpy 2.4.6` 已在 venv）；预留 `webrtcvad`/`silero` 可选升级分支。
4. **LLM 复用 py-service 内已有 OpenAI 兼容流式客户端**：[ai_provider.py](file:///z:/project/myblog/web3/py-service/modules/cockpit/app/services/ai_provider.py) 的 `stream_ai_text()` + `ai_configured()`（读项目 AI 设置页配置的 Key）。若未配置，则回退调用网关 `POST http://127.0.0.1:8080/api/agent/chat`（SSE，应用级令牌，前端 `@/api/agent` 已在用）。
5. **引导分两级**：确定性导航意图走**静态引导表**（route + tip，来自 `LOCAL_CMDS` 与 jarvis 的 `targetUrl`）；自由对话由 LLM 在回复末尾输出可选 `[[GUIDE]]{...}` JSON 块，前端解析后高亮。
6. **PCM 采集用 AudioWorklet**：文件放 `frontend/public/pcm-processor.js`（Vite 直接以根路径提供），不入 `src/`。
7. **WebSocket 走 Vite 代理直连 9006**：网关（`backend/gateway/.../application.yml`）只有 `/api/**`→9006 HTTP 转发、**无 WS 路由**，故新增 `/voiceapi`（`ws:true`，重写为 `/api/voice`），与既有 `/wifiapi`、`/osintapi` 同款写法。
8. **不引入服务端 TTS**、不引入前端 vosk（已禁用状态维持）。

## 4. 目标架构（数据流）

```
[麦克风] --getUserMedia{echoCancellation:true}--> AudioWorklet(pcm-processor.js)
        --16k Int16 / 800 样本(50ms) 二进制帧--> WS /voiceapi/ws --> py-service /api/voice/ws
                                                                      ├─ vad.py 能量 VAD（按 512 样本/32ms 判定）
                                                                      │    ├ 检测到开口 → 下发 {type:'interrupt'}（打断）
                                                                      │    └ 静音≥700ms → 下发 {type:'endpoint'}（说完了）
                                                                      └─ 收到用户文本（{type:'text'}，前端 Web Speech 转写）
                                                                            └─ llm.py 流式生成 → 按句切分 → 下发 {type:'sentence', text}
                                                                                 └ 前端 Edge TTS 队列逐句播放（首句即出）
                                                                                 └ 解析到引导 → 下发 {type:'guide', route, tip, selector?}
                                                                                      └ useVoiceGuide：router.push + 滚动 + 高亮 + 朗读
```

前端 WS 事件（服务端下发）：`ready | asr | text(增量) | sentence | guide | interrupt | endpoint | done | error`
前端 WS 上行：`{type:'start'} | {type:'text', text}（Web Speech 最终结果）| {type:'control', action:'stop'} | 二进制 PCM 帧`

## 5. 分阶段改动

### 阶段 1：TTS 流式化（低风险、首音延迟立降）

**文件**：[edgeTts.js](file:///z:/project/myblog/web3/frontend/src/api/edgeTts.js)

- **新增** `speakEdgeStream(text, voiceURI, { onSentenceStart, onSentenceEnd, onDone, onError })`：
  1. 复用现有 `splitSentences()` 拆句；
  2. 以并发窗口（最多 2-3 句）逐句调内部合成函数（复用现有 WebSocket 直连逻辑）拿到**每句独立 mp3 Blob**；
  3. 用共享 `AudioContext` + `decodeAudioData` + `AudioBufferSourceNode` 组成**播放队列**，第 1 句合成完立即 `start(0)` 播放，其余按序衔接；
  4. 暴露 `stopEdgeSpeechStream()`（`currentAudioSource.stop()` + 清空队列 + abort 未完成合成），与现有 `stopEdgeSpeech()` 合并为同一取消源；
  5. `onSentenceStart` 回调用于驱动"说话中"UI 与 `pulseOrbCore()`。
- **保留** 原 `speakEdge()` 导出以兼容其它调用方（全站仅 `XingTuAssistant.vue` 使用，可一并切换，但保留函数避免破坏）。

**验收**：对一段 4 句回复，首句音频开始播放时间应显著早于原实现（原为"整段合成完"）；`stopEdgeSpeech()` 在句间/句中均可立即静音。

### 阶段 2：前端全双工采集 + 打断 + 端点检测

**新建** `frontend/public/pcm-processor.js`（移植自 [AsLive pcm-processor.js](file:///z:/project/chat/AsLive-main/static/pcm-processor.js)，做低通平滑 + Bresenham 降采样到 16k + 800 样本/块 Int16 发送）。

**新建** `frontend/src/composables/useVoiceStream.js`：
- `startVoiceStream({ onEvent, onInterrupt })`：`getUserMedia({ audio: { echoCancellation:true, noiseSuppression:true, autoGainControl:false, channelCount:1 }})` → `AudioContext` → `audioWorklet.addModule('/pcm-processor.js')` → `AudioWorkletNode('pcm-processor')` → `port.onmessage` 把 `ArrayBuffer` 经 WS 二进制发送；
- 独立 WS 连接 `/voiceapi/ws`，支持 **3 秒指数退避重连**（参照现有 `scheduleRestart` 思路）；
- `send({type:'text', text})` 上行用户转写文本；`stop()`/`dispose()` 释放 track、worklet、audioContext、WS（**必须清理，防止内存泄漏**——项目既有约定）。

**修改** [XingTuAssistant.vue](file:///z:/project/myblog/web3/frontend/src/components/common/XingTuAssistant.vue)：
- `speak()`（L555-573）改造：**不再停麦克风**；改为 `await speakEdgeStream(...)`；并在 `onEvent` 收到 `interrupt` 时立即 `stopEdgeSpeech()` 并把当前 `isSpeaking` 复位；播完后**不强制**重启识别（识别保持常开）。
- **打断响应**：WS `interrupt` 事件 → `stopEdgeSpeech()` + `audioQueue=[]` + `statusText='已打断'`，把后续 Web Speech 结果当作新输入。
- **端点检测**：在 `recognition.onresult` 中维护"最后一次识别时间"；用 600-700ms 静音计时器触发 `respond(text)`，替代"仅靠 isFinal"；保留 `isFinal` 快速通道。
- **多轮上下文**：维护 `history`（最近 6-8 轮 `{role, content}`），随每次请求发送给服务端编排层。
- 删除/绕开原 `isSpeaking.value` 直接 return 的早退分支。

### 阶段 3：py-service 新增 `voice` 模块（服务端流式编排 + 引导）

**新建目录** `py-service/modules/voice/`（遵循 [modules/whisper](file:///z:/project/myblog/web3/py-service/modules/whisper/__init__.py) 契约，`core/loader.py` 自动发现，**无需改 `main.py`/启动脚本**）：

- `__init__.py`：`MODULE_META`（title="语音助手"、icon="🎤"）、`health()`（返回 `vad/llm/asr` 能力状态）、`setup/startup/shutdown`（可选，用于预加载）。
- `router.py`：`APIRouter(prefix="/api/voice", tags=["voice"])`；`@router.websocket("/ws")`。参考 [modules/osint/router.py#L78-L112](file:///z:/project/myblog/web3/py-service/modules/osint/router.py#L78-L112) 的 WS 样板。连接建立时**立即下发 `{"type":"ready"}`**（避免代理缓冲导致连接长期挂起——驾驶舱 SSE 既有教训）。
- `protocol.py`：事件常量与 `GuideStep` 结构定义。
- `vad.py`：`EnergyVAD`（纯 numpy）。帧长 512 样本/32ms；维护自适应噪声底（RMS 滑动分位）；`speech_start` 需连续 ≥N 帧超阈值；`endpoint` 需静音 ≥700ms（可环境变量调 `VOICE_SILENCE_MS`）；可选 `webrtcvad`/`silero` 分支（import 成功才启用）。
- `asr.py`：能力探测（`faster_whisper` 是否可导入）；`available()` 供 `health()` 与降级判断；本轮**不强制安装**，未装时服务端仅做 VAD/编排。
- `llm.py`：`stream_reply(messages)` → 优先 `ai_provider.ai_configured()` 时用 `stream_ai_text`；否则 `httpx` 流式 POST `http://127.0.0.1:8080/api/agent/chat`（OpenAI SSE，复用 [agent.js](file:///z:/project/myblog/web3/frontend/src/api/agent.js) 的上行体 `{messages}`）。System prompt 定义**星途助手人格 + 站点能力清单 + 引导规则**（要求回复口语化、单句简短、操作类意图输出 `[[GUIDE]]{...}`）。
- `guide.py`：`resolve_guide(user_text)` —— 命中静态导航意图表（移植 `LOCAL_CMDS` 的 path/reply 映射）返回 `{route, tip}`；否则从 LLM 输出里正则提取 `[[GUIDE]]` JSON 后剥离该块（该块**不朗读**）。
- **句子切分**：服务端按 `,，。！？；.!?;\n` 流式切句，逐句下发 `{type:'sentence', text}`（移植 AsLive `process_streaming` 的切句逻辑，TTS 交给前端）。

### 阶段 4：引导高亮层（前端）

**新建** `frontend/src/composables/useVoiceGuide.js`：
- `guideTo({ route, tip, selector })`：若 `route` 与当前不同则 `router.push(route)`；`await nextTick()` + `requestAnimationFrame` 等待渲染；
- 定位元素优先级：`selector` → `[data-voice-target]` → 页面 `<main>`/首个 `section` → 兜底全屏柔和蒙层 + 顶部提示条；
- 命中后 `el.scrollIntoView({behavior:'smooth', block:'center'})`，包裹一层**高亮描边 + 呼吸光圈**（绝对定位覆盖层，不修改原元素样式，退出时移除）；
- 复用 **已有 `GUIDE_PAGES` + 打字机小框**（L207-268）作为引导文案载体，扩展为"步骤引导"（支持多步 `next` 按钮）。

**约定**：在少量落地页容器上加 `data-voice-target="<key>"`（如首页/社区/商城/媒体/量化/工具），实现方在阶段 4 内按页面实际根元素补挂；缺省则自动降级到 `<main>`/蒙层，**不阻塞功能**。

### 阶段 5：接线与配置

- [vite.config.js](file:///z:/project/myblog/web3/frontend/vite.config.js)：`server.proxy` 新增
  `/voiceapi` → `http://127.0.0.1:9006`，`changeOrigin:true`，`ws:true`，`rewrite: p => p.replace(/^\/voiceapi/, '/api/voice')`。
- `XingTuAssistant.vue` 的 `respond()`（L802-841）改造为**新主路径**：
  1. 音乐指令（本地 `handleMusic`）保持不变；
  2. 导航意图：静态引导（`goLocal` → `guideTo`）+ 朗读；
  3. 其它：经 `useVoiceStream` 发 `{type:'text'}` 给服务端编排（LLM 流式 + 句子下发 + 引导）；
  4. 任一步失败（WS 断开/服务异常）→ **回退**现行 `recognizeVoice` → `agentRespond` 链路，保证可用性。
- `edgeTts.js` 的 `stopEdgeSpeech` 与 `useVoiceStream` 的 `interrupt` 处理统一收敛到单一"打断"入口 `interruptAll()`。

## 7. 降级与容错

- **WS 不可达**：前端回退现行"Web Speech + Edge TTS + jarvis/Agent"链路，功能不中断。
- **未配置 AI Key 且网关 Agent 不可用**：服务端 `llm.py` 抛错 → 下发 `{type:'error'}`，前端走 `goLocal` 静态回复 + 朗读。
- **服务端未装 faster-whisper**：`asr.available()=false`，服务端仅做 VAD + 编排；ASR 由前端 Web Speech 提供（默认路径）。
- **端口 9006 未运行**：`useVoiceStream` 重连退避并置 `voiceOk=false`，面板顶部提示"语音编排服务未启动，已降级"。

## 8. 验证方法

1. **启动**：`start-all-services.ps1` 起 MySQL/Redis/Nacos/Java/Vite/py-service；确认 `GET /api/voice/health`（经 `/voiceapi/health`）返回能力状态。
2. **全双工/打断**：唤醒星图 → 让助手说一段长回复 → 说话中途开口，观察 TTS **立即静音**、状态切"已打断"、新语句被识别并进入新一轮。
3. **首音延迟**：对 3-5 句回复，`performance.now()` 打点：从 LLM 首句 `sentence` 事件到首句音频 `onplaying`，应远小于原"整段合成"方案（目标 < ~1.2s，视网络）。
4. **轮次平滑**：连续 3-5 轮问答，无"识别空窗/抖动"，每轮静音约 0.7s 后自然结束。
5. **引导高亮**：说"打开商城"→ 助手朗读 + 跳转 `/shop` + 元素滚动到视野并高亮；随后 1 条"下一步建议"。
6. **降级**：临时停掉 9006，重复 2/5，确认回退链路仍可用且无报错刷屏。
7. **清理**：关闭面板/路由离开后，确认 `AudioContext`、`MediaStream tracks`、`WS`、定时器全部释放（DevTools 无悬挂）。
8. 浏览器控制台零报错；Vite 日志无 "Failed to scan for dependencies"。
